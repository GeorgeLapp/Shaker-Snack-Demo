# Документация Shaker-Snack-Demo

Этот каталог содержит основную техническую документацию проекта. Ниже — полный список документов
и краткое описание каждого файла.

---

## Список документов

- `telemetry.md` — модуль телеметрии: архитектура, API, форматы данных, сценарии синхронизации.
- `vending-controller-http-api.md` — HTTP API контроллера автомата (эндпоинты, параметры, ответы).
- `vending-controller.md` — контроллер: назначение, логика работы и взаимодействие с другими модулями.
- `payment-stack.md` — платёжный стек: архитектура, сценарии, интеграции, ключевые потоки.
- `mdb-rs232-cashless.md` — модуль MDB‑RS232 cashless: структура, константы, методы, сценарии.
- `purchase-module.md` — модуль покупки: фронт/бэк взаимодействие, сценарии, контракты.
- `service-menu.md` — сервисное меню: BFF + FSM, API, сценарии, навигация фронта.

---

## Как пользоваться

1) Начните с `service-menu.md` и `purchase-module.md` для понимания клиентских потоков.  
2) Для интеграций с контроллером — `vending-controller-http-api.md` и `vending-controller.md`.  
3) Для телеметрии и синхронизаций — `telemetry.md`.  
4) Для платежей — `payment-stack.md` и `mdb-rs232-cashless.md`.

---

## Расширенные описания разделов

Ниже — краткая структура ключевых разделов каждого документа, чтобы быстрее ориентироваться.

### `telemetry.md`

- Общая архитектура телеметрии и роли компонентов.
- HTTP API: синхронизация каталога, матрицы, остатков, продаж.
- Форматы данных, требования к полям, примеры payload.
- Сценарии синхронизации и обработка ошибок.

### `vending-controller-http-api.md`

- Полный список HTTP‑эндпоинтов контроллера.
- Команды, параметры, ответы, коды ошибок.
- Примеры запросов и типовые сценарии использования.

### `vending-controller.md`

- Описание назначения контроллера и общей логики.
- Компоненты и их взаимодействие.
- Особенности протоколов и ограничений.

### `payment-stack.md`

- Архитектура платёжного стека (cashless, драйверы, интеграции).
- Потоки оплаты (Product‑First и др.).
- Интеграции с backend и контроллером.

### `mdb-rs232-cashless.md`

- Общая структура модуля и константы протокола.
- Методы и обработка входящих/исходящих сообщений.
- Сценарии и типовые ошибки.

### `purchase-module.md`

- Полный фронт/бэк контракт по покупке.
- Методы, поля, форматы запросов/ответов.
- Сценарии успешной покупки и ошибки.

### `service-menu.md`

- BFF/FSM архитектура и формат ответов.
- Навигация фронта, сценарии и экраны.
- Контракты BFF и backend API.

---

## Связи и зависимости между документами

- `purchase-module.md` опирается на API из backend (`back/`) и на платёжный стек (`payment-stack.md`).
- `service-menu.md` зависит от backend сервиса и частично от телеметрии (`telemetry.md`).
- `mdb-rs232-cashless.md` дополняет `payment-stack.md`.
- `vending-controller-http-api.md` и `vending-controller.md` связаны с платёжным стеком и сервисным меню.

---

## Рекомендуемый порядок чтения

1) `service-menu.md` — понять BFF/FSM и навигацию UI.  
2) `purchase-module.md` — сценарии покупки и контракт фронт/бэк.  
3) `payment-stack.md` → `mdb-rs232-cashless.md` — глубина по платежам.  
4) `vending-controller-http-api.md` → `vending-controller.md` — контроллер и API.  
5) `telemetry.md` — телеметрия и синхронизация данных.

---

## Кто для кого (роли и аудитория)

| Документ | Кому полезен | Зачем читать |
|----------|-------------|--------------|
| `service-menu.md` | Frontend, backend, инженер ПНР | Навигация UI, BFF/FSM контракт, сценарии сервисного меню |
| `purchase-module.md` | Frontend, backend | Контракт покупки и сценарии фронт/бэк |
| `payment-stack.md` | Backend, интегратор платежей | Архитектура платёжного стека и интеграции |
| `mdb-rs232-cashless.md` | Backend, инженеры железа | Протокол и поведение cashless‑модуля |
| `vending-controller-http-api.md` | Backend, инженеры железа | Команды и API контроллера |
| `vending-controller.md` | Инженеры железа, backend | Назначение и внутренняя логика контроллера |
| `telemetry.md` | Backend, DevOps/интегратор | Синхронизация данных и интеграция с телеметрией |

Пояснение: **инженер ПНР** — инженер пусконаладочных работ, отвечает за ввод автомата в эксплуатацию,
настройку на площадке, проверку периферии и тестирование базовых сценариев.
